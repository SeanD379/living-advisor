# 上线前体验收口设计

## 目标

在保留首页户型图作为主要视觉内容的前提下，补齐原型上线前最影响理解、操作和稳定性的五个体验问题。

## 范围

### 1. 可识别住户头像

户型图中的三个住户入口继续使用按钮和房间中心定位，但按钮显示住户首字，并用边框/状态点表达“当前有待处理事项”。头像点击继续打开隐私安全的住户摘要，不显示手机号、地址或支付账号。

### 2. 我的状态入口

顶部“我的状态”入口保留在房名右侧，并显示当前与小陈有关的待处理数量。数量来自费用、值日和公约状态，不引入新的数据源；没有待办时显示“已完成”。

### 3. 弹窗与表单体验

弹窗支持点击遮罩关闭、Escape 关闭和键盘焦点约束；关闭后焦点回到触发按钮。表单字段使用显式 `for/id` 关联；金额和数量字段使用数字键盘提示。现有底部 sheet 视觉样式保持不变。

### 4. 关键动作防重复

公约确认采用幂等逻辑，已经确认的成员再次点击不会重复计数；付款入口在没有可付款账单时显示明确说明，不打开空白内容。已有 toast 反馈继续保留。

### 5. 上线级一致性

户型图 `aria-label` 和图片 `alt` 使用当前自定义房名；生活页日期展示使用当前日期推导，不再固定写死；按钮增加不改变布局的按压反馈，并在 375px 宽度下保持顶部房名和状态入口可用。

## 非目标

- 不新增首页四张大待办卡，避免削弱户型图主视觉。
- 不接入真实后端、支付、消息推送或新的头像图片资源。
- 不改变费用、值日、物品、公约的现有业务边界。

## 验收标准

- 三个住户入口均有可见首字，点击后仍能打开摘要。
- 顶部状态入口显示数量或“已完成”，并与操作后的本地状态同步。
- 弹窗可通过遮罩、Escape 和关闭按钮退出，焦点返回触发源。
- 公约确认重复点击不会增加确认人数；无可付款账单时不会抛出异常。
- 自定义房名在页面标题、户型图辅助文本中保持一致；测试和语法检查通过。
